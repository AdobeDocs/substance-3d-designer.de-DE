# Erfahren Sie mehr über die in Designer verwendeten Begriffe und Konzepte.

## #&#x200B;

|  |  |
| --- | --- |
| <b><span id="three-d-scene"></span>3D-Szene</b> | Eine Sammlung von Objekten und Daten, die bei der Darstellung und Animation einer Visualisierung des 3D-Raums eine Rolle spielen:<ul data-preserve-html="true"> <li data-preserve-html="true">[Gitter](#mesh)</li> <li data-preserve-html="true">[Materialien](#material)</li> <li data-preserve-html="true">Kameras</li> <li data-preserve-html="true">Lichter</li> <li data-preserve-html="true">Animation</li> <li data-preserve-html="true">Simulationen</li> <li data-preserve-html="true">...</li> </ul>[Beliebte Dateiformate](https://www.adobe.com/de/products/substance3d/discover/3d-files-formats.html) zum Speichern von 3D-Szenen sind die [USD](#usd) von Pixar und die FBX von Autodesk. Alle Dateiformate unterstützen nicht alle diese Komponenten |

## A

|  |  |
| --- | --- |
| <b><span id="alpha"></span>Alpha-Kanal</b> | Der vierte Kanal eines Farbbildes, der häufig zur Beschreibung der Deckkraft verwendet wird. |
| <b><span id="ambient-occlusion"></span>Umgebungs-Verdeckung</b> | Die Dämpfung von Umgebungslicht auf Oberflächen, die weniger belichtet und daher schwieriger zu erreichen sind. |
| <b><span id="anisotropy"></span>Anisotropie</b> | Die Eigenschaft, richtungsabhängig zu sein. Mit anderen Worten, ein anderes Ergebnis liefern, wenn auf einer anderen Achse gemessen oder beobachtet.   Anisotrope Materialien haben je nach Herkunft ein anderes Aussehen, und anisotrope Filter werden nicht in alle Richtungen gleichmäßig angewendet. |
| <b><span id="aov" ></span>AOV</b> | &quot;Arbitrary Output Variable&quot; (AOV) ist ein Begriff, der in [Rendering](#rendering) verwendet wird, um zusätzliche Datenkanäle zu beschreiben, die von einem Rendering ausgegeben werden können, z. B. Tiefe, Normale oder benutzerdefinierte Daten. |
| <b><span id="api"></span>API</b> | Eine API (Application Programming Interface) ist eine Sammlung von Funktionen und Prozeduren, mit denen Benutzer auf die Funktionen und Prozeduren einer anderen Anwendung des Programms zugreifen können.   Eine API bietet eine kontrollierte und sichere Ebene zwischen dem Benutzer und einem Programm. Es kann auch eine andere Programmiersprache verwenden, um die Interaktion mit diesem Programm zu vereinfachen und die Zugänglichkeit zu erweitern.   Designer bietet eine [Python-API](../scripting/scripting.md), die einfachen Zugriff auf eine breite Palette von Funktionen bietet, mit denen Daten bearbeitet, benutzerdefinierte Tools erstellt und Workflows beschleunigt werden können. |
| <b><span id="atomic-node"></span>Atomknoten</b> | Die grundlegenden Bausteine von Diagrammen. Alle [Instanzknoten](#instance-node) können in Diagramme atomarer Knoten unterteilt werden. Jeder Diagrammtyp hat seine eigenen atomaren Knoten. |

## B

|  |  |
| --- | --- |
| <b><span id="baking"></span>Backen</b> | Der Vorgang zum Berechnen von Informationen aus einem 3D-Modell und Speichern der Ergebnisse in einer [Textur](#texture). Die Daten werden in der Textur entsprechend den [UVs](#uv) des Modells platziert. |
| <b><span id="base-color"></span>Grundfarbe</b> (Albedo) | Ein Kanal eines [Materials](#material), der mithilfe des PBR-Modells &quot;Metallische Raueit [Schattierung](#shader)&quot; definiert wurde. Die Grundfarbe gibt die Farbe einer Oberfläche ohne Beleuchtungsinformationen an.   Es sollte nicht mit [Diffuse](#diffuse) verwechselt werden. |
| <b><span id="base-parameter"></span>Basisparameter</b> | Ein Parameter, der allen Knoten in einem Substance-Diagramm gemeinsam ist, die eine [Bitmap](#bitmap) berechnen.   Dazu gehören Kernaspekte der Bitmap, wie z. B. die Auflösung ([Ausgabegröße](#output-size)) und die [Bittiefe](#bit-depth) (Ausgabeformat), oder wie die Bitmap berechnet wird, z. B. im [Tiling](#tiling)-Modus.   Basisparameter werden häufig [von anderen Knoten geerbt](#inheritance), die stromaufwärts liegen, oder von dem Diagramm, das den Knoten hostet. |
| <b><span id="bilinear-filtering"></span>Bilineare Filterung</b> | Ein Interpolationsvorgang, der im Computerbild verwendet wird, wenn ein [Texturmuster](#texture-sampling) nicht genau in der Mitte eines Pixels ausgeführt wird.   Dies kann z. B. beim Vergrößern eines Bildes auftreten. |
| <b><span id="bit-depth"></span>Bittiefe</b> | Die Anzahl der Bits, die zum Speichern des Werts eines Pixels in einer Textur verwendet werden. Bei höheren Bittiefen können mehr Werte codiert werden, was zu glatteren Farbverläufen führt.   Je nach Werttyp stehen verschiedene Bittiefen zur Verfügung: - Ganzzahlige Werte können mit 8 Bit (0 bis 255) oder 16 Bit (0 bis 65.535) codiert werden. - Gleitkommawerte können mit 16 Bit (+32767,9999 bis -32768,0) oder 32 Bit (-3,4E+38 bis +3,4E+38) codiert werden. Bilder mit niedrigem Dynamikbereich verwenden Ganzzahlen, um die Schritte von 0 bis 1 zu codieren. High Dynamic Rangen verwenden Gleitkommawerte, um numerische Rohwerte zu codieren.   In Substance-Graphen wird die Bittiefe über den Parameter &quot;Ausgabeformat&quot; gesteuert. |
| <b><span id="bitmap"></span>Bitmap</b> | Ein digitales Bild. Zwei Arten von Bildern kommen am häufigsten vor:<ul data-preserve-html="true"> <li data-preserve-html="true">Graustufenbilder haben nur einen Kanal: Luminanz (L);</li> <li data-preserve-html="true">Farbbilder haben drei Kanäle: Rot, Grün und Blau (RGB). Ein vierter kann vorhanden sein: Alpha (A), das häufig für die Deckkraft verwendet wird. Farbbilder in Designer sind immer RGBA.</li> </ul>  Bitmaps können als Raster mit Werten aufgefasst werden. Jede Zelle dieses Rasters ist ein Pixel, das für &quot;Bildelement&quot; kurz ist. Ein Pixel speichert einen Wert pro Kanal. Der Typ dieses Werts hängt von der [Bittiefe](#bit-depth) der Bitmap ab. |

## C

|  |  |
| --- | --- |
| <b><span id="cache"></span>Cache</b> (Arbeitsspeicher) | Eine Datenerfassung - z. [Basisparameter](#base-parameter) und Ausgabebilder des Knotens - im Speicher gespeichert, um wiederverwendet zu werden.   Durch das Zwischenspeichern wird die Diagrammberechnung erheblich beschleunigt, da das [Substance Engine](#substance-engine) nur die Teile eines Diagramms neu berechnen kann, die sich geändert haben. Beim Anpassen von Knotenverbindungen und -parametern sind alle Knoten, die dem Knoten vorausgehen, von diesen Änderungen nicht betroffen. Daher müssen sie nicht erneut [ausgewertet](#evaluation) werden, um das Diagramm zu aktualisieren. Stattdessen wird ihr Cache verwendet.   Der Cache kann bei der Arbeit mit hohen Auflösungen und Bittiefen in großen Graphen einen erheblichen Speicherplatz beanspruchen. |
| <b><span id="channel-packing"></span>Kanal-Packing</b> | Eine Optimierungstechnik, bei der separate Bilder in die RGB(A)-Kanäle eines einzelnen Farbbildes gepackt werden.   Eine RMA-Textur ist beispielsweise eine Raueitskarte (R), eine Metalitätskarte (M) und eine Umgebungsfarbkarte (A), die alle in einer einzigen Farbtextur Verdeckung sind.   Eine weitere gängige Methode ist das Packing einer Graustufenstruktur in den Blaukanal einer Normalmap, da der Blaukanal - d.h. die &quot;Nach oben&quot;-Komponente des Normalvektors - zur Laufzeit neu berechnet werden kann.   Der Knoten [RGBA merge](../compositing-graphs/nodes-reference-for-com/node-library/filters/channels/rgba-merge/rgba-merge.md) ist nützlich für die Implementierung dieser Technik. |
| <b><span id="color-space"></span>Farbraum</b> | Eine Definition der Darstellung eines Farbbereichs. Die digitale Codierung und Decodierung einer bestimmten Farbe erfordert eine solche Definition, damit die verwendeten Zahlen einen Sinn ergeben.   In einer Bilddatei werden Farbwerte mit einem angegebenen Farbraum gespeichert, sodass diese Farben auf einem Display, das diesen Farbraum unterstützt, originalgetreu wiedergegeben werden können. Ein Display verfügt über spezielle Farbwiedergabefunktionen, die es ihm ermöglichen, einen bestimmten Farbraum ganz oder teilweise zu unterstützen.   Rohdaten - z. B. eine normale Karte - wird immer in einem linearen Farbraum codiert und decodiert, da diese Farben nicht visualisiert werden sollen und keine Transformationen auf diese Daten angewendet werden sollen.   sRGB ist ein weithin unterstützter Farbraum. Weitere beliebte Farbräume sind Adobe RGB, Rec. 2100 und ProPhoto RGB. |
| <b><span id="cooking"></span>Kochen </b>(<span id="compilation"></span>Kompilierung) | Der Prozess der Übersetzung von Daten in eine andere Sprache, damit sie schnell und effizient ausgeführt werden können. Um das Ergebnis eines Substance-Graphen zu berechnen, muss es zuerst kompiliert werden. Die Kompilierung ist Teil des [Evaluierungs](#evaluation)-Diagrammprozesses.   Diese Kompilierung wird für ein abgeflachtes Diagramm durchgeführt, was bedeutet, dass alle [Instanzknoten](#instance-node) durch ihre Quelldiagramme &quot;ersetzt&quot; werden, sodass ein größeres Diagramm verbleibt und dieses Diagramm kompiliert wird.   Ein kompiliertes Diagramm kann nicht bearbeitet werden. Verfügbare Parameter bleiben verfügbar, wenn sie [dynamisch](#dynamic-parameter) sind, während [statische](#static-parameter) Parameter gesperrt und ausgeblendet sind. |
| <b><span id="culling"></span>Ausrechnen</b> | Eine Optimierungstechnik zum Rendern von 3D-Szenen, bei der Geometrie aus den Berechnungen eines Renderings entfernt wird, wenn es nicht sichtbar ist.   Dies kann Objekte oder Polygone außerhalb des Kamerafrustums (*Frustum-Keulung*) einschließen, die entgegengesetzt zur Verdeckung gerichtet sind (*Rückseitenkeulung*) oder vollständig durch andere undurchsichtige Objekte ausgeblendet sind (*Kamerakeulung*). |

## D

|  |  |
| --- | --- |
| <b><span id="dependency"></span>Abhängigkeit</b> | Eine Datei A, die von einer anderen Datei B so verwendet wird, dass Datei B nicht wie vorgesehen funktioniert, wenn Datei A fehlt.   Eine Abhängigkeit eines [Pakets](#package) kann ein anderes Paket sein, da darin auf ein Diagramm, eine Bilddatei, eine Schriftart usw. verwiesen wird. Ein Paket speichert den Pfad zu seiner Abhängigkeit, und es wird eine Warnung ausgegeben, wenn die Abhängigkeit an diesem Pfad nicht gefunden werden kann. Fehlende Abhängigkeiten können auch zu [Geisterinstanzknoten](#ghost-instance-node) in einem Diagramm führen. |
| <b><span id="diffuse"></span>Diffus</b> | Ein Kanal eines [Materials](../glossary/glossary.md), der mithilfe des PBR-Modells &quot;Specular Glossiness [Schattierung](#shader)&quot; definiert wurde. Diffuse gibt die Farbe einer Oberfläche an, wenn sie beleuchtet wird.   Es sollte nicht mit [Grundfarbe (Albedo)](#base-color) verwechselt werden. |
| <b><span id="directx"></span>DirectX</b> | Eine Sammlung von APIs zur Verarbeitung von Multimedia-Inhalten. Die 3D-API Direct3D ist in der Entwicklung von Videospielen und anderen 3D-Branchen weit verbreitet.   Direct3D platziert den Ursprung einer Textur - d. h. ihre (0, 0)-Koordinate - an der *oberen linken Seite* (Y-unten), während die [OpenGL](#opengl)-API sie an der *unteren linken Seite* (Y-oben) platziert.   Das bedeutet, dass eine Normalmap der DirectX einen *invertierten grünen Kanal* im Vergleich zu OpenGL hat. Tatsächlich beherbergt der grüne Kanal die Y-Koordinaten der normalen Vektoren. |
| <b><span id="displacement"></span>Versatz</b> | Der Vorgang des Verschiebens der [Scheitelpunkte](#vertex) eines 3D-Modells, häufig entlang der [Normalen](#normal).   Versatz wird häufig in Kombination mit [tesselation](#tessellation) und [Normalmaps](#normal-map) verwendet, um detailliertere Informationen auf einer Oberfläche zu modellieren. |
| <b><span id="dynamic-parameter"></span>Dynamischer Parameter</b> | Ein Parameter, dessen Wert sich ändern kann. Mit anderen Worten, jeder Parameter, dessen Wert nicht konstant ist, ist dynamisch.    Dazu gehören exponierte Parameter, alle Parameter, die von einem exponierten Parameter betroffen sind, sowie alle Parameterwerte, die von [Sampling in einer Textur betroffen sind](#texture-sampling).   Im Gegensatz zu [statischen Parametern](#static-parameter) kann der Wert dynamischer Parameter spontan angepasst werden, nachdem das Diagramm in eine SBSAR-Datei kompiliert wurde. |

## E

|  |  |
| --- | --- |
| <b><span id="evaluation"></span>Auswertung</b> | Der Prozess der Auflösung der Weitergabe von Daten und Parametern im Diagramm. Die Auswertung überprüft die Gültigkeit eines Diagramms und seiner Verbindungen, wendet [Vererbung](#inheritance) an und [kocht](#cooking) das Diagramm.   In der Diagrammansicht wird eine Verbindung mit einer gepunkteten Linie dargestellt, wenn sie nicht ausgewertet wird. Die Auswertung wandelt die Verbindung in durchgehende Linien um.    Jedes Mal, wenn ein Parameter in einem Diagramm angepasst wird, werden der Knoten, der diesen Parameter hostet, und alle Knoten, die nachgelagert sind, [ungültig](#invalidation) und müssen erneut ausgewertet werden, bevor [gerendert](#rendering) wird. |

## F

|  |  |
| --- | --- |
| <b><span id="filter"></span>Filter</b> (Knoten) | Ein Knoten, der eine Änderung auf ein Bild anwendet (z. B. eine Deformation) oder Informationen daraus extrahiert (z. B. eine Maske). |

## G

|  |  |
| --- | --- |
| <b><span id="ghost-instance-node"></span>Ghost-Instanzknoten</b> | Ein [Instanzknoten](#instance-node), der auf einen nicht auffindbaren Untergraph verweist - d. h. eine fehlende [Abhängigkeit](#dependency) - wird als Geisterinstanzknoten geladen.   Geisterinstanzknoten werden in den erwarteten Zustand zurückgesetzt, indem die fehlende Abhängigkeit aufgelöst und das [Paket](#package) erneut geladen wird. |
| <b><span id="glossiness"></span>Glossarität</b> | Ein Kanal eines [Materials](../glossary/glossary.md), der mithilfe des PBR-Modells &quot;Specular Glossiness [Schattierung](../glossary/glossary.md)&quot; definiert wurde. Der Glanzgrad gibt die Unschärfe einer Fläche an, d. h. mikroskopische Variationen des Heights, auch als *Mikrofacetten* bezeichnet.   Hoher Glanz führt zu einem glatten Look, während niedriger Glanz zu einem rauen, matten Look führt.   Es ist das Gegenteil von [Raueit](#roughness). |

## H

|  |  |
| --- | --- |
| <b><span id="histogram"></span>Histogramm (Bild)</b> | Im Kontext eines Bildes repräsentiert ein Histogramm die Population der Werte in einem bestimmten Bereich - häufig [0, 1].   Diese Population wird mithilfe von vertikalen Balken dargestellt, wobei ein im Bild stärker vorhandener Wert zu einem höheren Balken für diesen Wert führt. Die Balken werden horizontal von niedrigen Werten (dunkel) bis hohen Werten (hell) verteilt.   Histogramme von Farbbildern überlappen normalerweise die Histogramme der einzelnen Kanäle - typischerweise R, G, B. |

## I

|  |  |
| --- | --- |
| <b><span id="inheritance"></span>Vererbung</b> | Im Kontext von Substance-Graphen beschreibt Vererbung die Eigenschaft von Nodes, die Parameterwerte von ihren Upstream-Nodes oder ihrem übergeordneten Graphen erfassen.   Zu den geerbten Parametern gehören [Auflösung](#resolution) ([Ausgabegröße](#output-size)), [Bittiefe](#bit-depth) ([Ausgabeformat](#output-format)) und [Unterteilung](#tiling)-Modus.   Erfahren Sie mehr über die Vererbung in dieser [dedizierten Seite](../compositing-graphs/inheritance-compositing/inheritance-in-substance-compositing-graphs.md). |
| <b><span id="instance-node"></span>Instanzknoten</b> | Ein Instanzknoten stellt ein Diagramm A in ein anderes Diagramm B dar. In diesem Fall kann Diagramm A als [Untergraph](#subgraph) von Diagramm B bezeichnet werden. Jede Änderung in Diagramm A wird an alle Instanzknoten weitergegeben, die es darstellen.   Der Instanzknoten wendet seinen eigenen Satz von Werten für die Eingabeparameter von Diagramm A im Kontext von Diagramm B an. In diesem Sinne kann Diagramm B mehrere Instanzknoten hosten, die alle auf Diagramm A verweisen, aber jeweils unterschiedliche Werte oder Texturen als Eingaben in Diagramm A übergeben.   Alle Knoten in der Designer-Bibliothek, die keine [atomaren Knoten](#atomic-node) sind, sind Instanzknoten. |
| <b><span id="invalidation"></span>Invalidierung</b> | Der Prozess, der erklärt, dass das Ergebnis eines Knotens veraltet ist.   Wenn ein Parameter angepasst wird, werden der Knoten, der diesen Parameter hostet, und alle Knoten stromabwärts ungültig. Daher müssen [ausgewertet](#evaluation) und [gerendert](#rendering) erneut ausgeführt werden. |

## M

|  |  |
| --- | --- |
| <b><span id="material"></span>Material</b> | Die Auflistung der Eigenschaften und Verhaltensweisen von Materie im Raum, die Oberflächen und Volumes umfasst. Das Erscheinungsbild einer Entität im 3D-Raum wird durch ihr Material definiert.   Materialien können auf verschiedene Weise definiert werden, und alle Definitionen unterstützen nicht alle Eigenschaften wie Brechung, Anisotropie oder Glanz. Ein [Shader](#shader) ist eine bestimmte Implementierung einer Materialdefinition.   <b>Wichtig:</b> Der Begriff &quot;Material&quot; ist ein *Dachbegriff*, der verwendet wird, um auf verschiedene Dinge zu verweisen, einschließlich:<ul data-preserve-html="true"> <li data-preserve-html="true">Der [Shader](#shader), der zum Berechnen des Erscheinungsbilds einer Oberfläche oder eines Volumes verwendet wird;</li> <li data-preserve-html="true">Der Satz von [Texturen](#texture), der einem Shader bereitgestellt wird;</li> <li data-preserve-html="true">Eine Material-ID, bei der es sich um ein Attribut einer 3D-Grundform handelt, die verwendet wird, um die Teile zu unterscheiden, die verschiedene Materialien verwenden.</li> </ul> |
| <b><span id="mesh"></span>Mesh</b> | Ein 3D-Objekt, das aus [Scheitelpunkten](#vertex) besteht, die durch Kanten zu Polygonen - wie Dreiecken - verbunden sind, die wiederum zu Flächen zusammengefügt werden. Diese Flächen können offen oder geschlossen sein.   Das Erscheinungsbild dieser Flächen wird durch das ihnen zugewiesene [Material](#material) definiert. Der Detailgrad eines Gitters ist ebenfalls stark von seinem [Polycount](#polycount) abhängig. |
| <b><span id="metadata"></span>Metadaten</b> | Daten, die Informationen über die Datei selbst, ihre Umgebung oder andere mit den Daten der Datei zusammenhängende Informationen bereitstellen.   Zu den gängigen Metadaten gehören der Autor der Datei, das Erstellungs- und Änderungsdatum, das Copyright und die Titelgrafik.   In Designer kann der Inhalt eines [Pakets](#package) auch Metadaten enthalten. Beispielsweise kann ein Substance-Diagramm, das ein Stoffmaterial erzeugt, Metadaten für die physikalischen Eigenschaften des Stoffes enthalten. |
| <b><span id="mipmap"></span>MIPMAP</b> | Eine kleinere Version einer Textur, die oft automatisch berechnet wird.   Eine Textur kann eine Pyramide kleinerer Versionen von sich selbst haben, die zur Laufzeit austauschbar sind, sodass die für optimale Qualität und Leistung am besten geeignete Größe verwendet wird.   Eine Textur mit hochfrequenten Details, die in kleinerer Größe angezeigt werden, erzeugt wahrscheinlich *Moiré*-Artefakte. Darüber hinaus enthält eine größere Textur wahrscheinlich mehr [Texturbeispiele](#texture-sampling).   Der Begriff &quot;mipmap&quot; stammt aus der MIP-Zuordnungstechnik, bei der &quot;MIP&quot; für das lateinische &quot;*multum in parvo*&quot; steht, was &quot;viele Dinge an einem kleinen Ort&quot; bedeutet. |

## H

|  |  |
| --- | --- |
| <b><span id="node"></span>Knoten</b> | Objekt in einem Diagramm, das Berechnungen ausführt und ein oder mehrere Ergebnisse ausgibt.   Das Ergebnis wird mithilfe von Eingabeparametern gesteuert. Diese Parameter können als Steuerelemente im Eigenschaften-Dock oder als Eingangsanschlüsse auf dem Knoten selbst aufgeführt werden.   Es gibt zwei Hauptkategorien von Knoten: [atomare Knoten](#atomic-node) und Instanzknoten. |
| <b><span id="noise"></span>Rauschen</b> | Ein nicht-figuratives Bild, das eine zufällige oder pseudo-zufällige Verteilung von Formen und Farben darstellt. Lärm wird oft verwendet, um Flächen und Deformationen zu variieren.   Die Knotenbibliothek von Designer umfasst eine große Sammlung von Rauschgeneratoren, z. B. [BnW Spots](../compositing-graphs/nodes-reference-for-com/node-library/texture-generators/noises/bnw-spots-2/bnw-spots-2.md), [Clouds](../compositing-graphs/nodes-reference-for-com/node-library/texture-generators/noises/clouds-2/clouds-2.md), [Perlin noise](../compositing-graphs/nodes-reference-for-com/node-library/texture-generators/noises/perlin-noise/perlin-noise.md) oder [Voronoi](../compositing-graphs/nodes-reference-for-com/node-library/texture-generators/noises/voronoi/voronoi.md). |
| <b><span id="normal"></span>Normal</b> | Bei der 3D-Berechnung ist die Normale einer Oberfläche ein [normierter](#normalization)-Vektor, der senkrecht zu dieser Oberfläche verläuft und von dieser Oberfläche nach außen verläuft.   Dieser Vektor stellt die Ausrichtung einer Fläche im 3D-Raum dar und wird für [Schattierung](#shader) verwendet, die entsprechend den Lichtern und der Kameraperspektive der Szene angezeigt wird.   Eine [normale Map](#normal-map)-Textur kann auf eine Oberfläche angewendet werden, um ihre Normalen zu ändern und Details hinzuzufügen. |
| <b><span id="normal-map"></span>Normale Zuordnung</b> | Eine Struktur, die auf eine Oberfläche angewendet wird, um ihre Normalen zu ändern.   Es wird am häufigsten verwendet, um Details zu fälschen, die in der Geometrie eines Modells ineffizient wären. Die Verwendung einer solchen Karte ermöglicht es, zusätzlich zu den Pro-Scheitelpunktnormalen auch Pro-Texel-Normalen zu haben, was zu mehr Oberflächeninformationen und damit zu mehr Oberflächendetails führt.   Die X-, Y- und Z-Koordinaten der Normalenvektoren sind in den roten, grünen bzw. blauen Kanälen der Karte kodiert. Je nach Zielgrafik-API ([DirectX](#directx) oder [OpenGL](#opengl)) ist der grüne Kanal möglicherweise invertiert. |
| <b><span id="normalization"></span>Normalisierung</b> | Der Prozess der Neuzuordnung eines Wertebereichs in den Bereich [0, 1], wobei der höchste Eingabewert auf 1,0 und der niedrigste Eingabewert auf 0,0 neu zugeordnet werden.   Bei Vektoren passt die Normalisierung die Länge des Vektors (oder &quot;Magnitude&quot;) auf einen Wert von 1,0 an. |

## O

|  |  |
| --- | --- |
| <b><span id="opengl"></span>OpenGL</b> | Ein API für 3D-Grafiken, das in der Entwicklung von Videospielen und anderen 3D-Branchen weit verbreitet ist.   OpenGL platziert den Ursprung einer Textur - d. h. ihre (0, 0) Koordinate - an der *unteren linken Seite* (Y-nach oben), während die [DirectX](#directx)-API sie an der *oberen linken Seite* (Y-nach unten) platziert.   Das bedeutet, dass eine OpenGL-Normalmap einen *invertierten grünen Kanal* im Vergleich zu DirectX hat. Tatsächlich beherbergt der grüne Kanal die Y-Koordinaten der normalen Vektoren. |
| <b><span id="openusd"></span>OpenUSD</b> | Siehe [USD](#usd). |

| <b><span id="package"></span>Paket</b> | Eine Substance 3D-Datei ([SBS](#sbs-file)) wird als Paket bezeichnet, da sie ein Container für Ressourcen ist: Diagramme, [Bitmaps](#bitmap), [3D-Szenen](#three-d-scene) usw. Ein Paket speichert auch Pfade zu seinen [Abhängigkeiten](#dependency) sowie [Metadaten](#metadata). |

B. gekachelt, nach dem Zufallsprinzip gestreut oder nach bestimmten Regeln angeordnet). |
| <b><span id="pixel-ratio"></span>Pixelverhältnis</b> | Dieser [Basisparameter](#base-parameter) steuert die Kompensation des Bildseitenverhältnisses auf Pixelebene. Mit anderen Worten: ob die Pixelgröße ausgeglichen werden soll, um ein quadratisches Verhältnis in einem nicht quadratischen Bild zu erhalten.   Der Parameter wird von nicht-lokalen Filtern verwendet, d. h. Filtern, die die Werte benachbarter Pixel verwenden, um den Wert eines Pixels zu berechnen. |
| <b><span id="pixel-size"></span>Pixelgröße</b> | Dieser Basisparameter definiert die horizontale und vertikale Größe eines Pixels.   Er dient als Multiplikator für nicht lokale Filter, d. h. Filter, die die Werte benachbarter Pixel verwenden, um den Wert eines Pixels zu berechnen. |
| <b><span id="polycount"></span>Polycount</b> | Die Anzahl der Polygone eines 3D-[Gitters](#mesh). Vielmehr ist Polycount die Abkürzung für &quot;Polygonanzahl&quot;.   Mehr Polygone können feinere Details erzeugen. Gitter mit einer niedrigen Polyzahl werden als &quot;low-poly&quot; bezeichnet, während höhere Polyzahlen als &quot;high-poly&quot; bezeichnet werden. |
| <b><span id="primary-input"></span>Primäre Eingabe</b> | Der Eingangsconnector eines [Instanzknotens](#instance-node), von dem dieser Knoten seine [Basisparameter](#base-parameter)-Werte erbt.   Die primäre Eingabe ist in ihrem Connector mit einem kleinen Punkt und dem Suffix &#39;(Primary)&#39; in ihrer Beschriftung gekennzeichnet.   Bei der Verwendung von Knoten mit mehr als einer Eingabe wird *dringend* empfohlen, darauf zu achten, welche ihrer Eingaben die primären sind und wie sich dies auf die [Vererbung](#inheritance) im gesamten Diagramm auswirkt. |
| <b><span id="procedural"></span>Procedural</b> | Das Merkmal einer Daten oder eines Artefakts, das durch Befolgen eines Computeralgorithmus erstellt wird, anstatt manuell.   Designer verwendet einen prozeduralen Arbeitsablauf, bei dem der Algorithmus als Knotendiagramm gestaltet ist.     Prozedurale Workflows ermöglichen schnellere Iterationen, da Variationen und Anpassungen schnell generiert werden können, indem der Algorithmus und seine Parameter geändert werden.   Wenn das Ergebnis vollständig vom Algorithmus erzeugt wird, wird dieses Ergebnis umgangssprachlich als &quot;100% prozedural&quot; bezeichnet. Die prozedurale Generierung wird manchmal auf &quot;proc-gen&quot; gekürzt.   Die meisten Generatoren in der Knotenbibliothek von Designer sind zu 100 % verfahrenstechnisch, da sie kein Eingabebild benötigen, um ein Ergebnis zu erzielen. |
| <b><span id="publishing"></span>Veröffentlichen (SBSAR)</b> | In Designer bezieht sich die Veröffentlichung auf das Exportieren eines [Pakets](#package) als SBSAR-Archivdatei, die [kompilierte](#compilation) Versionen der Diagramme, ihre Ressourcen ([Bitmaps](#bitmap), Schriften usw.), ihre Vorgaben sowie ihre [Metadaten](#metadata) enthält.   Die resultierende SBSAR-Datei kann dann über ein [Substance 3D-Plug-in](https://substance3d.adobe.com/plugins/) verteilt und in anderen Substance 3D-Anwendungen oder Anwendungen von Drittanbietern verwendet werden. |

Diese Archivdatei wird verwendet, um kompilierte Substance 3D Designer-Diagramme und die erforderlichen Ressourcen ([Bitmaps](#bitmap), Schriften usw.) zu speichern.   SBSAR ist das Hauptdateiformat zum Verteilen von Substance-Graphen, die von anderen Substance 3D-Anwendungen und Substance 3D-Plug-ins verwendet werden können.   Da die in SBSAR-Dateien gespeicherten Graphen kompiliert werden, können sie nicht in Substance 3D Designer geladen und bearbeitet werden. SBSAR-Dateien können jedoch mit [7Zip](https://www.7-zip.org/) geöffnet werden, um ihre Parameter, Vorgaben und Metadaten in einer eingebetteten [XML](#xml)-Datei abzurufen. |

| <b><span id="shader"></span>Shader</b> | Programm, das das Erscheinungsbild einer Oberfläche oder eines Volumes gemäß seinen [Materialeigenschaften](#material), dem Licht, das es empfängt, und dem Ort, von dem aus es betrachtet wird, berechnet. Ein Shader ist eine besondere Implementierung einer Materialdefinition.   Texturen können einem Shader zur Verfügung gestellt werden, um sein Verhalten zu steuern. Es können auch Rohwerte verwendet werden. Wechseln Sie in der [3D-Ansicht](../interface/3d-view/3d-view.md) zum Menü &quot;Materialien&quot;, um zu sehen, welcher Shader von einem Material in der aktuellen Szene verwendet wird. Über das Menü können Sie auch auf die [Shader-Eigenschaften](../interface/3d-view/3d-view.md) zugreifen und sehen, welche Texturen und Werte derzeit vom Shader verwendet werden.   &#39;Shader&#39; wird manchmal synonym mit &#39;[Material](#material)&#39; verwendet. |
| <span id="sheen"></span><b>Glanz</b> | Der Glanz oder Glanz eines Stoffes.   Dieser Begriff ist in der Textilindustrie weit verbreitet, um eine reflektierende Eigenschaft zu beschreiben, die eine subtile farbige Helligkeit hinzufügt. |
| <b><span id="signed-distance-field"></span>Feld für signierte Entfernung (SDF)</b> | <p>Ein vorzeichenbehaftetes Abstandsfeld ist eine mathematische Funktion, die eine Oberfläche im 3D-Raum definiert, indem der Abstand von einem beliebigen Punkt im Raum zum nächsten Punkt auf der Oberfläche berechnet wird.</p><p>Erfahren Sie hier mehr über das Konzept und seine Verwendung in Designer: [Arbeiten mit SDF-Funktionen](../function-graphs/nodes-reference-for-fun/function-node-library/function-nodes-sdf-functions/working-with-sdf-functions.md#what-is-an-sdf-function).</p> |
| <b><span id="spline"></span>Spline</b> | Im Allgemeinen ist eine Kurve, die mithilfe einer mathematischen Funktion modelliert wurde, die es ermöglicht, saubere und glatte Formen mit jeder Auflösung zu zeichnen. Designer verwendet eine verlustbehaftete Näherung, die in einer Textur mit einem benutzerdefinierten Datenformat codiert ist.   Splines bieten intuitive Steuerelemente für Länge und Flugbahn, beinhalten andere Daten wie Thickness und Height und bieten an jedem Punkt entlang einen einfachen Zugriff auf Entfernung und Richtung.   Diese Eigenschaften machen sie zu einem leistungsstarken Werkzeug für das Zeichnen und Texturieren. |
| <b><span id="static-parameter"></span>Statischer Parameter</b> | Ein Parameter, dessen Wert sich nicht ändern darf.   Im Gegensatz zu [dynamischen Parametern](#dynamic-parameter) können statische Parameter nicht sofort geändert werden, wenn das Diagramm in eine SBSAR-Datei kompiliert wird. Sie können in Designer nur angezeigt und geändert werden, wenn das Diagramm erstellt wird.   Der Vorschaumodus blendet diese Parameter in einigen Fällen aus, da er darauf abzielt, das Verhalten veröffentlichter SBSAR-Dateien so genau wie möglich abzugleichen.   Eine Liste der statischen Parameter ist hier [&#x200B; verfügbar](../compositing-graphs/manage-parameters/exposing-a-parameter/exposing-a-parameter.md). |

| <b><span id="substance-engine"></span>Substance Engine</b> | Eine proprietäre Technologie, die vom Substance 3D-Team entwickelt wurde und für die Bildberechnung zuständig ist, indem eine große Anzahl von Transformationen, Effekten und Compositing von Eingabebildern sehr effizient durchgeführt wird.   Das Substance Engine implementiert und berechnet die [Atomknoten](#atomic-node) von Designer.   Die Engine wird über verschiedene Backends implementiert, je nach Plattform, auf der sie ausgeführt wird: CPU, GPU und Betriebssystem. In Designer können die Backends umgeschaltet werden, indem Sie zu [Tools > Modul wechseln](../interface/the-main-toolbar/the-main-toolbar.md) wechseln gehen.   Einige Backends bieten eine deutlich bessere Leistung als andere - z. B. ist das GPU-Backend viel schneller als die CPU - und die Ergebnisse können bei den Backends leicht unterschiedlich sein. |

| <b><span id="tessellation"></span>Tesselation</b> | In der Computergrafik ist Tesselierung der Prozess, eine Oberfläche in mehrere Polygone, oft Dreiecke, zu unterteilen.   Dieser Prozess kann zur Laufzeit ausgeführt werden, um die Anzahl der Polygone eines 3D-Modells dynamisch zu erhöhen, häufig in Verbindung mit [Versatz](#displacement) und [Normalmaps](#normal-map), um mithilfe der hinzugefügten Polygone detailliertere Modelle zu erstellen. |

In den meisten Fällen erfordert diese Effizienz Texturen, um die Leistung von zwei Auflösungen zu nutzen - z. B. 1024 x 1024, 4096 x 4096, 512 x 256 usw. |

| <b><span id="tiling"></span>Kacheln</b> | Die horizontale, vertikale oder beide Wiederholungen eines Bildes ohne sichtbare Nähte oder visuelle Diskontinuität.   Designer bietet viele [Knoten](#node), die [Geräusche](#noise) oder [Muster](#pattern) erzeugen, die diese Kachel bilden. Dementsprechend sind viele [filter](#filter)-Knoten so konzipiert, dass sie Bilder verarbeiten und dabei die Unterteilung beibehalten. |

## U

|  |  |
| --- | --- |
| <b><span id="usage"></span>Nutzung (Ausgabe)</b> | In Substance-Graphen ist eine Verwendung ein Attribut eines [Ausgabeknotens](../compositing-graphs/nodes-reference-for-com/atomic-nodes/output/output.md), der verwendet wird, um der Anwendung mitzuteilen, wie eine [Textur](#texture) mit dem [Shader](#shader) in der [3D-Ansicht](../interface/3d-view/3d-view.md) verbunden werden kann.   Wenn Sie ein Substance-Diagramm auf die 3D-Ansicht anwenden, werden alle Ausgänge auf der Grundlage entsprechender Verwendungen mit dem Shader verbunden. | <b><span id="udim"></span>UDIM</b> (UV-Kacheln) | Ein Standard zum Aufteilen des [UV](#uv)-Raums in Kacheln mit einem eindeutigen numerischen Bezeichner, mit dem jeder Kachel eine andere Textur zugewiesen werden kann.   UDIM-Workflows sind in VFX-Pipelines gang und gäbe, wo High-Fidelity-Assets so viele Details erfordern, dass mehrere hochauflösende Texturen erforderlich sind. In diesem Fall werden die [UV](#uv)s des Assets über mehrere UDIM-Kacheln (oder UV-Kacheln) angeordnet.   Designer unterstützt UDIM-Workflows und kann pro UDIM ein anderes Substance-Diagramm zuweisen. |
| <b><span id="usd"></span>USD</b> (oder OpenUSD) | Die [Universal Scene Description](https://openusd.org/release/index.html) (USD) ist ein von Pixar erstelltes 3D-Szenenbeschreibungsformat, das für Interoperabilität und Datenaustausch über Anwendungen und Plattformen hinweg entwickelt wurde.   USD-Dateien enthalten die Definition der in einer Szene verwendeten Daten sowie die Komposition dieser Szene und alles, was sie beinhaltet: Modelle, Materialien, Kameras, Animationen, Simulationen usw. Eine USD-Datei kann jede Art von Daten enthalten, vorausgesetzt, die Anwendung hat Zugriff auf das USD-Plugin, mit dem sie diese Daten richtig lesen und verwenden kann.   Adobe ist [&#x200B; an der Alliance for OpenUSD](https://blog.adobe.com/en/publish/2023/08/01/powering-3d-interoperability-continued-collaboration-through-openusd) beteiligt, einem Konsortium von Akteuren der 3D-Branche, die aktiv zur Entwicklung und Standardisierung des Formats beitragen. |
| <b><span id="uv"></span>UV</b> | UVs sind eine Darstellung eines 3D/Modells auf 2D-Fläche. Sie werden verwendet, um 2D-Bilder aus 2D-Flächen der Oberfläche des Modells in 3D-Flächen zuzuordnen.   Die Erstellung von UVs wird häufig als das Schneiden von Nahtstellen in das Modell beschrieben, um es zu auseinander zu falten und zu glätten. |
